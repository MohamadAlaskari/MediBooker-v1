# Mobile app (Expo)

`apps/mobile` (`@medibooker/mobile`) is the patient app for iOS and Android, the main channel for patients. It follows the `react-native-screen` skill. Practice selection follows [ADR 0005](../adr/0005-multi-tenancy.md); animation follows [ADR 0008](../adr/0008-animation-gsap.md).

## 1. Stack

- Expo SDK 58 (`expo ~58.0.22`), React Native 0.88.1 (New Architecture, Hermes), React 19.3.0, Expo Router `~58.0.29`, TanStack Query.
- react-native-reanimated 4.7.1 with react-native-worklets 0.13.0 for motion. GSAP and shadcn/ui are web-only.
- i18n binding: use-intl on the shared ICU catalogue (ADR 0013).
- Native and SDK packages are added only with `npx expo install`; SDK upgrades follow §14.

## 2. Structure

```text
apps/mobile/
  app/                          Expo Router routes, kept thin
    _layout.tsx                 splash until fonts and locale are ready; LocaleProvider; AppProviders; ErrorBoundary
    index.tsx                   shell home; tabs and the auth gate from A06
    +not-found.tsx
    (dev)/kit.tsx               UI kit preview (X09)
    (dev)/intl-check.tsx        plural, number, date and RTL samples (X08)
  src/
    providers/                  app-providers.tsx
    lib/                        env.ts, api.ts, query.ts, locale.ts, direction.ts, version.ts,
                                practice.ts (A06), offline-cache.ts (B05)
    theme/                      ThemeProvider, useTheme, createStyles
    components/ui/              design-system components (X09)
    features/<feature>/         hooks, components, schemas.ts, index.ts
  app.config.ts · eas.json · metro.config.js · jest.config.js · eslint.config.js · expo-env.d.ts · .env.example
```

The `(dev)` routes exist only when `__DEV__` is true or the build sets `EXPO_PUBLIC_E2E=1` (X10). `android/` and `ios/` are generated by prebuild and never committed.

## 3. Configuration

- **`app.config.ts`:**
  - `scheme: 'medibooker'` for token-free navigation, `userInterfaceStyle: 'automatic'`;
  - `ios.bundleIdentifier` and `android.package` are placeholders derived from `APP_VARIANT` until decision D6;
  - `android.allowBackup: false`, so app storage stays out of Android Auto Backup;
  - `experiments: { reactCompiler: true }`;
  - plugins: `expo-router`; `['expo-localization', { supportedLocales: { ios: locales, android: locales } }]` with `locales` imported from `@medibooker/i18n/locales.json` (committed JSON, because Expo and EAS evaluate this file before any workspace build); `['expo-font', { fonts }]` with the TTFs of `@expo-google-fonts/inter` and `@expo-google-fonts/noto-sans-arabic`; `['expo-build-properties', { android: { usesCleartextTraffic: false } }]` for every variant except development;
  - later plugins: `expo-secure-store` (A06), `expo-calendar` (B05), `expo-notifications` (N02).
- **No `expo-updates`:** it is not installed until the DPO approves EAS Update or an in-region update server exists, because every app start would contact the update service. REL01 then adds it with `runtimeVersion: { policy: 'fingerprint' }`.
- **`eas.json`:** profiles `development`, `preview` and `production`, each with `EXPO_PUBLIC_API_ORIGIN` (https for preview and production; a CI check from F07) and, from REL01, pinned `node` and `pnpm` versions. No credentials.
- **`metro.config.js`:** `getDefaultConfig(__dirname)` only (§13).
- **`expo-env.d.ts`** is committed (its content is the static line `/// <reference types="expo/types" />`), so `tsc` passes on a clean checkout.
- **tsconfig:** `extends: ["@medibooker/tsconfig/strict.json", "expo/tsconfig.base"]`, in this order, so Expo's `DOM` and `ESNext` libs win.

## 4. Navigation and practice selection

- Expo Router file routes; screens live in `src/features`.
- `_layout.tsx` wraps the root `<Stack />` in Expo Router's `<LocaleProvider direction>`, so headers and gestures follow the reading direction.
- A06 adds the `(tabs)` layout with the auth gate and the practice selection (`lib/practice.ts`):
  - the selected practice comes from a practice-page link, a QR code or `GET /api/v1/me/practices`, which lists the practices of the account (id, slug, name, capacity) from the platform database;
  - the selection is stored in `expo-secure-store` and used in every practice-scoped API path; the API checks it on every request (ADR 0005 §3);
  - switching practices clears the query cache and the offline cache, and the theme switches to the practice's brand.
- "My appointments" across practices uses `GET /api/v1/me/appointments?scope=upcoming` (B03). The response can list `unavailablePractices` with a reason; the screen shows what loaded and a banner: a retry for `UNAVAILABLE` and `TIMEOUT`, a hint to open the practice directly for `LIMIT` (more than 20 practices, ADR 0005 §9.1). History is loaded per practice.
- Links that carry tokens (verification, password reset, invitations, "this was not me") open the web page, which reads the token from the URL fragment. The app never receives tokens through links. The custom scheme carries IDs only; every deep link requires sign-in first and validates its parameters as UUIDs. Verified App Links and Universal Links for token-free paths arrive with REL01, once decision D6 fixes the identifiers.

## 5. Providers

`src/providers/app-providers.tsx`, outermost first:

1. `SafeAreaProvider`
2. `ThemeProvider` (§8)
3. the i18n provider with messages and named formats; `timeZone` is `UTC` until a practice is selected, then the practice's zone
4. `QueryClientProvider` with `createQueryClient()`
5. `VersionGate`: compares the app version with `minimumSupportedVersion` from `GET /api/v1/public/app-config` and shows a blocking screen with the store link when it is lower
6. `OfflineBanner`

`lib/query.ts` connects `focusManager` to `AppState` and `onlineManager` to NetInfo.

## 6. API client

- `lib/env.ts` validates `EXPO_PUBLIC_API_ORIGIN` with zod and requires `https:` unless `__DEV__` (the Android emulator uses `http://10.0.2.2:3001` in development).
- `lib/api.ts`: `configureApiClient({ baseUrl, credentials: 'omit', getHeaders })` with `Accept-Language` and `X-App-Version`. From A06 the Bearer token comes from secure storage; one refresh is in flight at a time, and a 401 triggers a refresh and one retry.
- A 503 for one practice (its database is unavailable or being migrated) shows the retry state for that practice only; the account and other practices stay usable.
- Bookings send an `Idempotency-Key` and reuse it on retry.
- Logout clears secure storage (tokens and the selected practice), the query cache, the offline cache (§10) and the push token.

## 7. i18n and RTL

- **Locale:** the stored choice (AsyncStorage; a locale is not personal data), else the device locale (`expo-localization`), else `ar`.
- **Direction:** SDK 58 enables RTL when `supportedLocales` declares Arabic. `lib/direction.ts`: when `I18nManager.isRTL` differs from `getDirection(locale)`, call `I18nManager.allowRTL(true)` and `I18nManager.forceRTL(isRtl)`, then `reloadAppAsync()` from `expo`, which reloads without `expo-updates`. In Expo Go the device language decides.
- **Layout:** `start`/`end` style props only (lint); directional icons mirror with `transform: [{ scaleX: -1 }]` when `I18nManager.isRTL`; clocks, check marks and the logo never mirror.
- **Text:** the `Text` component sets `textAlign` and `writingDirection`. Phone numbers, e-mails and IDs inside Arabic text are wrapped with `isolateLtr()`; code inputs stay LTR.
- **Hermes Intl:** X08 verifies Arabic plural categories (zero, one, two, few, many, other), `numberingSystem: 'arab'` and time-zone formatting on a device with `app/(dev)/intl-check.tsx`. `src/lib/intl-polyfills.ts` adds `@formatjs` polyfills only for gaps found there. X10 runs the same screen nightly on an Android emulator.

Catalogue, formats and bidi rules: [05](05-errors-i18n-tokens.md).

## 8. Theme

- `src/theme/`: `ThemeProvider` combines `useColorScheme()` with the practice's brand scale through `createColorTheme(scheme, brandScale)` from `@medibooker/design-tokens`; the brand is Teal until a practice is selected (ADR 0002). `useTheme()` and `createStyles()` give components typed tokens.
- Tokens come from `src/generated/tokens.ts`; hex literals are a lint error.
- Touch targets are at least 44 × 44 pt (`hitSlop` for small icons); font scaling is never disabled; layouts wrap at the largest text sizes; two-pane layouts from 600 dp (Figma page "Tablet Layouts").

## 9. Motion

react-native-reanimated with the motion tokens: durations in milliseconds and `Easing.bezier` built from the token control points. `useReducedMotion()` true means the end state applies at once. Horizontal motion follows `I18nManager.isRTL`. Only transforms and opacity are animated.

## 10. Offline data

- In memory, the TanStack Query cache keeps data readable offline; the `OfflineBanner` marks it read-only. Booking and cancelling need a connection.
- Across restarts (B05), only an allowlisted projection of upcoming appointments is persisted: `appointmentId`, `practiceId`, `startsAt`, practice name and status, at most the next ten. No service, provider or note, because a service name is health data.
  - The projection is chosen with `dehydrateOptions.shouldDehydrateQuery` and stored as one value in `expo-secure-store` with `keychainAccessible: WHEN_UNLOCKED_THIS_DEVICE_ONLY`, which excludes it from backups and device transfers.
  - If it ever outgrows the secure store's value size, it moves to an AES-GCM-encrypted file whose key stays in the secure store.
- The persisted value is purged on logout, on an account or practice switch and when a token refresh fails.
- Jest tests assert that the persisted value contains no service name and is empty after logout.

## 11. Error boundaries and states

- `app/_layout.tsx` exports `ErrorBoundary({ error, retry })`, which renders the localized error screen with the request id in small print for 5xx.
- The shared helpers from `@medibooker/api-client` (`errorMessageKey`, `applyFieldErrors`) map errors to messages and fields. Blocking errors use an `Alert`, transient ones a toast announced with `AccessibilityInfo.announceForAccessibility`. The full flow is in [05](05-errors-i18n-tokens.md).

## 12. Testing

- **`jest.config.js`:**
  - `preset: 'jest-expo'` (`~58.0.13`, Jest 30.5.2), with `projects` for `jest-expo/ios` and `jest-expo/android` where `Platform.select` matters;
  - `passWithNoTests: false`; reporters `default` and `github-actions`; in CI `--ci --json --outputFile=test-results/jest.json`;
  - `transformIgnorePatterns`: jest-expo's default alternation extended with the binding's ESM packages (`use-intl`, `intl-messageformat`, `@formatjs` for option B; `i18next`, `react-i18next`, `i18next-icu` for option A) and `@medibooker`;
  - `globalSetup` sets `process.env.TZ = 'Pacific/Chatham'`.
- **No MSW in Jest.** MSW 3, faker and the Orval mocks ship ESM-only `.mjs` builds that jest-expo does not transform. Mobile tests inject a route-table fake through `configureApiClient({ fetch })`, for example `fakeFetch({ 'GET /api/v1/public/app-config': { status: 200, body } })`, with hand-written fixtures typed `satisfies AppConfigResponse`. Transport and error mapping are proven by the api-client's own Vitest suite.
- `@testing-library/react-native` 14.1.0 with `test-renderer` 1.3.0, the version jest-expo uses; explicit `@jest/globals` imports.
- **What Jest proves:** props (`accessibilityRole`, label, state), `allowFontScaling` never false, hit areas computed from style size plus `hitSlop`, no `numberOfLines` on body text, cache purge on a practice switch, the partial-result banner of the cross-practice list.
- **What only a device proves:** layout, Hermes Intl, `forceRTL` with reload, offline behaviour. These are covered by the X08 intl-check screen, the X10 emulator job and the recorded manual checks per feature (VoiceOver and TalkBack in Arabic and English, the largest text size, a 375 pt device and a large one).
- **CI quality job:** `expo export --platform android --platform ios --output-dir dist` (Metro resolution), `npx expo install --check`, and `expo-doctor` with the React Native Directory check disabled (`EXPO_DOCTOR_ENABLE_DIRECTORY_CHECK=0`); the weekly scheduled workflow runs that check without blocking.

## 13. Metro in the monorepo

- Expo supports pnpm's isolated `node_modules`; `getDefaultConfig` sets watch folders and resolution, so there are no manual `watchFolders`. The fallback, if a native module breaks, is `nodeLinker: hoisted` for the whole workspace, recorded in ADR 0006.
- One React copy: pnpm `overrides` pin `react`, `react-dom` and the React types to the catalog version (F07), and a CI check fails when the lockfile resolves more than one version of `react` or `@tanstack/react-query`.
- Workspace packages consumed through Metro: `@medibooker/api-client` (source), `@medibooker/i18n` and `@medibooker/design-tokens` (built; `turbo dev` keeps them rebuilt with `tsc -b -w`).

## 14. Expo SDK upgrade runbook

1. Read the SDK release notes and note the React and React Native versions it pins.
2. Set the catalog entries and the pnpm `overrides` for `react`, `react-dom` and their types to the SDK's React version; the web moves with them.
3. In `apps/mobile`: `npx expo install --fix`, then `npx expo install --check` and `npx expo-doctor`.
4. Run `pnpm verify`, dispatch the X10 emulator job and repeat the recorded device checks.
5. Approve the held Renovate updates for Expo-managed packages on the dependency dashboard.
